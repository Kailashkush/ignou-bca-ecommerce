# Deploying ShopSphere

Two free services and one free database. Total cost: nothing. Total time: about
twenty minutes, most of it waiting for builds.

```
  MongoDB Atlas  ◀──  shopsphere-api   ◀──  shopsphere-web
  (free M0 tier)      (Render web)          (Render static site)
                       Express + Node        React build output
```

Render has no managed MongoDB, which is why the database sits on Atlas and is
handed to the API through one environment variable.

---

## 1. Database — MongoDB Atlas

1. Sign up at <https://www.mongodb.com/cloud/atlas/register>.
2. **Create a cluster** → choose **M0 (Free)** → region **Mumbai (ap-south-1)**
   if offered, otherwise the nearest.
3. **Database Access** → *Add New Database User*:
   - username `shopsphere`
   - password: click *Autogenerate*, then **copy it somewhere safe**
   - role: *Read and write to any database*
4. **Network Access** → *Add IP Address* → **Allow access from anywhere**
   (`0.0.0.0/0`).
   Render's free tier has no fixed outbound IP, so an allow-list of one address
   will not work. This is the documented trade-off of the free tier; the
   database is still protected by the user credential.
5. **Connect** → *Drivers* → copy the connection string. It looks like:
   ```
   mongodb+srv://shopsphere:<password>@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority
   ```
6. Replace `<password>` with the real password, and insert the database name
   before the `?`:
   ```
   mongodb+srv://shopsphere:REALPASSWORD@cluster0.xxxxx.mongodb.net/ecommerce_db?retryWrites=true&w=majority
   ```
   Keep this string. It is the `MONGO_URI` below.

   > If the password contains `@`, `:`, `/` or `#`, percent-encode it — an
   > unescaped `@` will split the URI in the wrong place and the connection will
   > fail with an unhelpful DNS error.

---

## 2. Services — Render

1. Sign up at <https://render.com> and connect your GitHub account.
2. **New → Blueprint** → select this repository.
   Render reads `render.yaml` and proposes two services:
   `shopsphere-api` and `shopsphere-web`.
3. It will ask for the four values marked `sync: false`:

   | Variable | Value |
   |---|---|
   | `MONGO_URI` | the Atlas string from step 1.6 |
   | `SEED_ADMIN_PASSWORD` | a password of your choosing for the admin account |
   | `CLIENT_ORIGIN` | `https://shopsphere-web.onrender.com` |
   | `VITE_API_BASE_URL` | `https://shopsphere-api.onrender.com` |

   `JWT_SECRET` is generated by Render — you never see it and it is never
   committed. Everything else is already set in `render.yaml`.
4. **Apply**. The first build takes five to ten minutes.
5. **Check the real URLs.** If a name is already taken, Render adds a suffix
   (for example `shopsphere-api-x7k2.onrender.com`). Open each service and
   compare its URL with what you typed. If they differ, fix the variable under
   *Environment*. Saving it redeploys the service. `CLIENT_ORIGIN` must match the
   site's URL exactly, with `https://` and no trailing slash, or the browser
   blocks every request with a CORS error.

---

## 3. Seed the database

The deployed database starts empty. Seed it **once**, from your own machine,
pointing at Atlas rather than at localhost:

```bash
cd ecommerce-app/server
MONGO_URI='mongodb+srv://shopsphere:REALPASSWORD@cluster0.xxxxx.mongodb.net/ecommerce_db?retryWrites=true&w=majority' \
SEED_ADMIN_PASSWORD='the same password you gave Render' \
npm run seed
```

This inserts 6 categories, 34 products, 6 users and 40 demonstration orders.

> `npm run seed` **deletes every document** in all four collections before
> inserting. That is what you want on a fresh deployment and emphatically not
> what you want later. The script refuses to run when `NODE_ENV=production`.

---

## 4. Check it

```bash
curl https://shopsphere-api.onrender.com/api/health
# {"success":true,"status":"ok","timestamp":"..."}
```

Then open `https://shopsphere-web.onrender.com` and sign in:

| Role | Email | Password |
|---|---|---|
| Customer | `ananya@example.com` | `Customer@123` |
| Administrator | `admin@shopsphere.test` | whatever you set as `SEED_ADMIN_PASSWORD` |

---

## 5. Put the URLs in the report

```bash
# edit report/links.py, set GITHUB_URL and LIVE_URL
cd report
python3 gen_qr.py        # renders the two QR codes
python3 build_print.py   # rebuilds the PDF with the Project Resources page
```

The Project Resources page appears automatically once at least one URL is set,
and is omitted entirely when neither is.

## Things that will catch you out

**The free tier sleeps.** After 15 minutes without traffic Render suspends the
API, and the next request takes 30–60 seconds while it restarts. For a viva,
open the site a few minutes beforehand so it is warm. The report says so on the
Project Resources page, so an examiner who hits the delay knows why.

**Atlas free tier pauses after 60 days idle.** Log in once in a while, or the
cluster suspends and the demo goes down without warning.

**Both services must finish deploying before the site works.** If the web
service builds first you will briefly see the page load but every API call fail.
Wait for both to show *Live*.

**Check the logs, not the browser.** Render's dashboard → service → *Logs* shows
the real error. A blank page with a CORS message in the browser console almost
always means `CLIENT_ORIGIN` on the API does not match the web service's actual
URL (see step 2.5).
